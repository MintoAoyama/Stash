# Stash

`data/works/` の JSON から静的サイトを生成する。変更された作品に関係するページだけを作り直す。

## データ

作品1件が1ファイルで、その作品の記録（`logs`）を内包する。

- パスは `data/works/<idの末尾1文字>/<id>.json`（例: `data/works/k/mgx3a1k.json`）
- `id` はファイル名（拡張子を除く）と一致させる
- 末尾1文字で分けるのは、GitHub がディレクトリあたりの項目数を3,000件以下にするよう推奨しているため
- 形式の正本は [`schema/work.schema.json`](schema/work.schema.json)
- `src/work-file.ts` は、そこから `npm run gen` で生成した型。手では編集しない

| 項目 | 内容 |
|---|---|
| `type` | 種類。未知の値は `other` として描画する |
| `path` | `/` 区切りのディレクトリ（例: `movies/2026`）。空でもよい |
| `tags` | タグの配列 |
| `season` | 放送クール（例: `2026-autumn`。冬・春・夏・秋は `winter`・`spring`・`summer`・`autumn`）。空でもよい |
| `episodeCount` | 全話数。任意で、放送中は分からないことが多いので、終了後に分かったときに入れる |
| `channel` | 放送局。空なら、記録の放送情報でいちばん多い放送局（同数なら最新の記録のもの）を使う |
| `genres` | ジャンル。番組表（ARIB STD-B10）のコードを主なものから順に並べたもの（`30` はドラマ/国内ドラマ、`5` はバラエティ）。ページは大分類だけを区別し、シーズンのページは 1 番目の大分類の見出しで分ける。一覧のカードには 1 番目の大分類を出す |
| `airtime` | 放送枠（例: `日曜 21:00〜21:45`）。自由な文字列。シーズンのページは、先頭の曜日と時刻で月曜から並べる（番組表と同じく 5:00 を一日の区切りにし、`平日` は月曜とみなす）。読めない作品は後ろに回す |
| `officialUrl` | 公式サイトの `https` の URL。作品ページにリンクを出す |
| `logs[]` | 記録（項目は下記） |

`logs[]` の項目:

- `id`: ページの URL の一部になるので、スキーマの形式で作品内に重複させない
- `author`: 表示名
- `loggedAt`: `YYYY-MM-DD`。記録した日（観た・読んだ・聴いた日）
- `rating`: 1〜5
- `text`: Markdown（[本文の書式](#本文の書式)を参照）
- `episode`: 話数
- `episodeEnd`: 1件でまとめて見たときの最後の話
- `subtitle`: サブタイトル
- `program`: 放送情報。`source` が `nhk` の記録を載せるページは、フッターに NHK のクレジットを出す

### 記録の日付

記録には 2 つの日付がある。`loggedAt`（記録した日）と、`program.date`（放送日）。

- 放送情報のある記録は、放送日に属する。日付の表示、作品ページの並び、月・週・年のページ、一覧のカードの日付と新しさ、過去の今日が、これに従う
- 放送情報のない記録は、`loggedAt` に属する
- 放送日と `loggedAt` が違う記録には、もう一方の日を添える（作品ページ・記録ページ・月・週のページは「2026-10-18 鑑賞」、トップの最近の記録は「2014-11-27 放送」）
- トップの最近の記録、日ごとの記録数（活動の集計）は、`loggedAt` のまま。記録した順に並べるための表示だから
- 同じ作品の話数の並び（前後の記録、視聴状況）は、記録した順のまま

スキーマが禁止するのは、描画すると誤りになるものだけ。余分なプロパティや未知の `type`、空の任意項目は許容する。

### 本文の書式

記録の `text` は Markdown として [markdown-it](https://github.com/markdown-it/markdown-it) で描画する（`src/markdown.ts`）。書いた側でプレビューする場合は、同じ版と設定にそろえる。

- 1つの改行もそのまま改行にする（`breaks`）。Markdown を使わずに書いた文章は、段落と改行がそのまま出る
- HTML は書けない（`html: false`）。書いた HTML は文字として出る
- `https://` と `http://` で始まる URL は、そのまま書いてもリンクになる
  - 日本語は URL の後に空白を入れずに続けることが多いので、URL は ASCII の印字可能文字までで終わり、末尾の句読点は含めない
  - `example.com` のようなスキームのない書き方とメールアドレスはリンクにしない
- 見出しは h3 から始める（`#` が h3）。ページには作品名の h1 と、書いた人の h2 があるため
- 表は、幅が広ければその表だけ横にスクロールする

## 生成されるページ

| パス | 内容 |
|---|---|
| `/` | トップ |
| `w/<idの末尾1文字>/<id>/` | 作品 |
| `w/<idの末尾1文字>/<id>/<logId>/` | 記録1件（全文、同じ書き手の前後の記録、他の書き手の同じ話の記録へのリンク） |
| `type/<type>/` | 種類ごとの一覧 |
| `d/…` | `path` に沿ったディレクトリの一覧 |
| `t/`、`t/<tag>/` | タグの一覧、タグごとの一覧 |
| `s/`、`s/<yyyy>-<season>/` | シーズンの一覧、シーズンごとの作品 |
| `m/<yyyy>/`、`m/<yyyy>/<MM>/` | 年ごと、月ごとの記録 |
| `m/<yyyy>/<MM>/w<n>/` | 週ごとの記録。週は月曜から日曜で、木曜が入る月の第 n 週（2026-08-01 の土曜は「2026年7月5週目」）。月のページから、その月の記録がある週へリンクする |
| `data/site.json` | トップが使う集計（下記） |

`data/site.json` の中身:

- 件数（種類ごと、シーズン数、書いた人の数を含む）
- シーズンごとの作品。トップが、開いた日のシーズンの作品を、記録した新しい順に 6 件まで、最新の記録のダイジェスト付きのカードで出すのに使う
- 最近の記録（`loggedAt` の新しい順に 60 件。放送日が違うものは、放送日を添える）。トップは、開いた日のシーズンの作品の記録を除いて、9 件までをダイジェスト付きのカードで出す
- ダイジェストは、作品ページで長い記録を途中までにするのと同じく、記法を除いて 140 字で切る
- 年ごと・月ごとの件数（放送日の年月）。トップのアーカイブ（年ごとの行に月のマスを並べた一覧）が使う
- 過去の今日（放送日の月日）
- 日ごとの記録数（`loggedAt`）

各ページの HTML にはそのページ自身の内容だけを入れる。

- 記録が増えるたびに変わる値は `data/site.json` に分け、ブラウザ側の JS（`assets/site.js`）がトップに差し込む。1件の追加で作り直すページを、関係するものだけに絞るため
- ナビゲーションの種類・シーズンのリンクも HTML では隠しておき、記録のあるものだけ JS が表示する
- 書いた人の名前（記録の横と、視聴状況の行の見出し）も同じく隠しておき、データ全体で書いた人が2人以上になったら JS が表示する。1人だけのうちは、名前を出しても区別の役に立たないため
- 一覧の絞り込み（種類・ジャンル・書いた人）は JS を使わず、`:has()` とラジオボタンの CSS だけで動く

### 記録の見せ方

- 長い記録は、作品ページでは途中までにして、全文を記録のページに置く
  - 途中までにするときは、Markdown の記法を除いた文字にしてから切る。記法の途中で切れて崩れないようにするため
  - 短い記録と記録のページは Markdown として描画する
  - 月・週の一覧の抜粋も、記法を除いた文字にする
- 話数のある記録がある作品の作品ページとシーズンのページには、書いた人ごとの視聴状況を、話数のマス目として載せる
- 作品ページの各記録の番組情報は、短くする
  - 作品の情報の行と重なる局名を省く。作品に放送枠があれば、時刻と番組名も省く
  - 放送日は記録の日付として見出しに出る。記録した日が違うときだけ、番組情報にも「2026-10-11 21:00–21:54 放送」と載せ、「2026-10-18 鑑賞」を続ける（同じ年なら月日だけ）
  - こうして短くなった番組情報は、別の行にせず記録の日付と評価の後ろに続ける
  - 記録のページには番組情報をすべて載せる

### クレジット

出典が求めるクレジットは、その情報を載せるページのフッターにだけ出す。

- NHK: 記録の `program.source` が `nhk` のものを載せる作品・記録のページ
- TMDB: `externalIds.tmdb` のある作品、または TMDB の画像（`https://image.tmdb.org/`）をカバーにした作品を載せるページ
  - 作品と記録のページのほか、そういう作品を含む一覧（種類・ディレクトリ・タグ・シーズン・年）
  - 月・週のページとトップには出さない（作品名しか載せないため）

### カバー画像

カバー画像はない作品のほうが多い前提で組む。

- 画像がなければ代わりの枠も出さず、文字だけで並べる
- 一覧にカバーのある作品が1つもなければ、カードの幅を広げる

### Jekyll が配信しない名前

Jekyll を使う GitHub Pages は `_` や `.` で始まる名前を配信しない。

- 出力のパス名は、先頭をこれらから `-` に置き換える
- 前回のコミットを記録する `.source-sha` は、配信されない名前にしてある

## 差分ビルド

出力ディレクトリの `.source-sha` に前回ビルドしたコミットを残し、そこから HEAD までの差分で作り直すページを決める。

- `data/works/` 以下の JSON の変更: その作品の変更前と変更後が属するページ（作品、記録、種類、ディレクトリ（祖先を含む）、タグ、シーズン、年月）だけを作り直す
  - 中身がなくなったページは削除する
- サイトの出力に関係しないファイルだけの変更: ページは変わらない（対象は `src/data.ts` に定義している）
- 次の場合は、全件を作り直す
  - 上記以外の変更（`src/`、`assets/`、`site.config.json` 等）
  - `.source-sha` がない
  - 前回のコミットが見つからない
  - `--full` を付けた

内容が変わらないページは書き込まない。

## 検証

全作品ファイルをスキーマで検証する。

- 違反（不正な JSON、`id` とファイルパス（ディレクトリを含む）の不一致を含む）が1つでもあれば、何も書き出さずに終了コード1で止まる
- GitHub Actions では `::error file=...` の注釈として違反を出す
- `.source-sha` は進まないので、公開は前回の状態のまま止まり、データを直した次のビルドで追いつく

## 設定

`site.config.json`:

| キー | 内容 |
|---|---|
| `title` | サイト名 |
| `basePath` | 公開するパス。`/` で始まり `/` で終わる（環境変数 `BASE_PATH` で上書きできる） |
| `cname` | 任意。指定すると出力に `CNAME` と `.nojekyll` を置く |

## 開発

TypeScript はビルドせず、そのまま実行する。

```sh
npm ci
npm test
npm run check
npm run build -- --out out          # 差分ビルド（out/.source-sha がなければ全件）
npm run build -- --out out --full   # 全件ビルド
```

## デプロイ

ワークフローが、GitHub App のトークンで配信用リポジトリを checkout し、`site.config.json` の `basePath` に対応するディレクトリへビルド結果を push する。

公開するのは main だけで、手動で実行するときに別のブランチを選んでも何もしない。

マージ前の確認には `preview` ブランチを使う。

- ここに push したものが、`stash-preview/` に全件ビルドで公開される（`.github/workflows/preview.yml`）
  - 記録のデータは main の最新を使い、全ページに `noindex` を付ける
  - push したコミットにこのワークフローが含まれている必要がある
- 試したいブランチは、`git push -f origin <ブランチ>:preview` でいつでも入れ替えられる
- 試し終えたら `git push -f origin main:preview` で main に戻す
  - コード（`data/works` 以外）が main と同じなら、`stash-preview/` を消す

| 種類 | 名前 | 内容 |
|---|---|---|
| Variable | `APP_CLIENT_ID` | GitHub App の Client ID |
| Variable | `DEPLOY_REPO_NAME` | 配信用リポジトリの名前（同じオーナー） |
| Secret | `APP_PRIVATE_KEY` | GitHub App の秘密鍵 |
